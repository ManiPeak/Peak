# Peak روی اندروید — اجرای کامل روی خود گوشی (بدون سرور و VPS)

نسخهٔ اندروید **عین نسخهٔ PC** کار می‌کند: رانتایم Node.js داخل خود APK است، سرور
Next.js و بات ماینکرفت و دیتابیس همگی **روی خود گوشی** اجرا می‌شوند و WebView
به `http://127.0.0.1:3784` (درون همان دستگاه) وصل می‌شود. هیچ سرور، VPS یا
«ریموت‌کنترلی» در کار نیست.

## معماری (عین electron/main.js)

```
┌─ Peak.apk ────────────────────────────────────────────────┐
│  پوستهٔ Kotlin (MainActivity + NodeService)                │
│    └─ پل JNI (node-jni.cpp) → node::Start                 │
│         └─ libnode.so (nodejs-mobile 18.20.4 — arm64)      │
│              └─ node node_modules/next/dist/bin/next start │
│                   └─ سرور Next روی 127.0.0.1:3784          │
│                        ├─ بات ماینکرفت + AI + SQLite       │
│                        └─ WebView ← http://127.0.0.1:3784  │
└────────────────────────────────────────────────────────────┘
```

- **رانتایم Node**: `libnode.so` از بستهٔ npm
  [`nodejs-mobile-react-native@18.20.4`](https://www.npmjs.com/package/nodejs-mobile-react-native)
  (Node 18.20.4 — MODULE_VERSION 108) به‌همراه هدرهای کامل — توسط
  `scripts/prepare-android-assets.mjs` استخراج می‌شود. هیچ فایل باینری در Git نیست.
- **نصب اپ روی گوشی**: assets (`.next` + `node_modules` پروداکشن + `package.json` +
  `next.config.mjs` + `public`) در اولین اجرا به `filesDir/app` استخراج می‌شوند —
  دقیقاً همان ساختار `resources/app` در ویندوز.
- **داده‌ها**: دیتابیس SQLite مثل PC در پوشهٔ `data/` زیر filesDir برنامه می‌ماند.
- **جلوگیری از خواب**: سرویس پیش‌زمینه + WakeLock تا بات هنگام قفل بودن صفحه زنده بماند.
- **پالایش‌ها**: عین `scripts/build-exe.ps1` — حذف `minecraft-data/{bedrock,doc,tools}`،
  `test/tests`، `*.md`/`README*`، و `@next/swc-*` و `@img/*` (بیلد-تایم / sharp).

## ساخت APK

### راه ۱ — GitHub Actions (توصیه‌شده)

ورک‌فلوی `.github/workflows/build-android.yml` با هر push به main یا تگ `v*` یا
اجرا دستی:

1. `npm ci` + `npm run build` (بیلد Next)
2. `node scripts/prepare-android-assets.mjs` (استخراج libnode + مونتاژ assets)
3. `scripts/build-android-native.sh arm64-v8a` (کراس‌کامپایل `better-sqlite3` با NDK r26d)
4. `gradle assembleRelease` (Gradle 8.7 + JDK 17 — بدون نیاز به Gradle wrapper در Git)
5. آپلود artifact به‌نام `Peak-<version>.apk` (+ پیوست به Release در تگ‌ها)

### راه ۲ — لوکال

پیش‌نیاز: JDK 17، Android SDK + NDK r26+، Node 22، Gradle 8.7.

```bash
npm ci && npm run build
node scripts/prepare-android-assets.mjs
export ANDROID_NDK_HOME=~/Android/Sdk/ndk/26.3.11579264
bash scripts/build-android-native.sh arm64-v8a
cd android && gradle assembleRelease
# خروجی: android/app/build/outputs/apk/release/app-release.apk
```

نسخهٔ APK به‌صورت خودکار از `package.json` خوانده می‌شود (الان 1.0.2).

## نصب روی گوشی

1. فایل `Peak-1.0.2.apk` را از بخش Assets دانلود کنید (یا artifact ورک‌فلو).
2. روی گوشی: **Settings → Apps → Special access → Install unknown apps** را برای
   مرورگر/فایل‌منیجر موردنظر فعال کنید.
3. APK را باز کرده و **Install** بزنید (با کلید debug امضا شده — پیام «unsafe» طبیعی است).
4. اولین اجرا چند ثانیه طول می‌کشد (استخراج فایل‌ها)؛ بعد رابط Peak بالا می‌آید.
5. برای باتِ پیوسته، گزینه‌های **Battery optimization → Don't optimize** را برای Peak
   فعال کنید تا اندروید سرویس را نکشد.

## پرسش‌های متداول

**چرا WebView و نه React Native؟**
برای اینکه «عین نسخهٔ PC» باشد: همان کد Next، همان بات، همان دیتابیس — فقط پوستهٔ
UI به‌جای BrowserWindow الکترون، WebView اندروید است.

**چرا فقط arm64-v8a؟**
تمام گوشی‌های مدرن arm64 هستند. برای شبیه‌ساز x86_64: `gradle assembleRelease -PpeakAbis=x86_64`
(و `PEAK_ABIS=x86_64` برای اسکریپت آماده‌سازی).

**بات هنگام بستن اپ؟**
سرویس پیش‌زمینه ادامه می‌دهد؛ با ضربه روی نوتیفیکیشن برمی‌گردید. برای اجرای همیشگی،
بهینه‌سازی باتری را خاموش کنید (بالا).

## بخش ۱ — دانلود و نصب (کاربر نهایی)

### کدام فایل را بردارم؟

در صفحهٔ [Releases](https://github.com/ManiPeak/Peak/releases/latest) فقط دو فایل معنی دارند:

| فایل | برای چه کسی | چه می‌کند |
|---|---|---|
| **`Peak-Setup-Latest.exe`** | تقریباً همه | نصب روی ویندوز — میان‌بر دسکتاپ + منوی استارت |
| **`Peak-Portable-Latest.exe`** | اجرای بدون نصب | فقط اجرا می‌شود؛ مناسب فلش و سیستم مهمان |

لینک‌های ثابت (همیشه آخرین نسخه):

* نصب‌کننده: <https://github.com/ManiPeak/Peak/releases/latest/download/Peak-Setup-Latest.exe>
* پرتابل: <https://github.com/ManiPeak/Peak/releases/latest/download/Peak-Portable-Latest.exe>

فایل‌های دیگری که ممکن است در صفحهٔ ریلیز ببینی:

* `Peak-Setup-<نسخه>.exe` و `Peak-Portable-<نسخه>.exe` — همان دو فایل بالا، با شمارهٔ نسخه (آرشیو).
* `Peak.exe` / `node.exe` / `elevate.exe` — اجزای *داخل* بسته‌اند؛ برای نصب برشان ندار.

### نصب با نصب‌کننده — فقط ۳ قدم

1. `Peak-Setup-Latest.exe` را اجرا کن.
2. در نصب‌کننده **فقط محل نصب را انتخاب کن** (یا پیش‌فرض را رها کن) و
   **بقیهٔ گزینه‌ها را دست نزن** — میان‌بر دسکتاپ و منوی استارت از پیش روشن‌اند.
3. **Install** را بزن. تمام ✅

**هیچ پیش‌نیازی لازم نیست.** Node.js داخل خود بسته است (`resources/node/node.exe`)؛
نیازی به نصب Node.js، Python، Visual Studio یا git نیست.

### نسخهٔ پرتابل

فایل را هرجا (حتی روی فلش) بگذار و اجرا کن. داده‌های برنامه (دیتابیس، حافظهٔ دائمی،
تنظیمات) در `%APPDATA%\Peak\data` ذخیره می‌شوند، پس چیزی روی خود فلش نوشته نمی‌شود.

### اگر ویندوز هشدار داد

برنامه هنوز امضای دیجیتال ندارد؛ این هشدارها طبیعی‌اند:

| هشدار | کار |
|---|---|
| SmartScreen («Windows protected your PC») | **More info** ← **Run anyway** |
| فایل بلاک‌شده | راست‌کلیک روی فایل ← **Properties** ← تیک **Unblock** ← **OK** |
| آنتی‌ویروس | فایل/پوشهٔ نصب را در استثناها (Exclusion) بگذار |

### اگر میان‌بر «Missing Shortcut» داد

میان‌بر خراب = هدفش سر جایش نیست. رایج‌ترین علت‌ها و راه‌حل‌ها:

| علت | راه‌حل |
|---|---|
| Defender/آنتی‌ویروس `Peak.exe` را بعد از نصب قرنطینه کرده | Add exclusion + **دوباره نصب کن** |
| میان‌بر به فایل موقت نسخهٔ پرتابل در `%TEMP%` اشاره دارد (پاک شده) | میان‌بر جدید بساز و مستقیم به خود `Peak-Portable-Latest.exe` بده |

نکتهٔ فنی: نام اجرایی در config بسته‌بندی پین شده (`executableName: Peak`) تا میان‌برهای
نصب‌کننده همیشه به `Peak.exe` اشاره کنند و با تغییر نسخه خراب نشوند.

### برنامه باز نشد؟

فایل `%APPDATA%\Peak\data\peak-log.txt` را باز کن؛ خط‌های `[FATAL]` علت دقیق را
می‌گویند (معمولاً یکی از این دو: Node داخل بسته نیست، یا بیلد Next داخل بسته نیست).

## بخش ۲ — ساخت EXE

### پیش‌نیاز ساخت (فقط برای سازنده)

* ویندوز ۱۰/۱۱ (۶۴ بیت)
* Node.js نسخهٔ ۲۰ به بالا — **فقط برای ساخت**؛ خودِ برنامه نیاز به Node ندارد

### ساخت خودکار (پیشنهادی)

با هر `push` روی `main`، ورک‌فلوی **Build Windows EXE** در گیت‌هاب خودش همه‌کار را می‌کند:

1. `scripts/build-exe.ps1` را اجرا می‌کند (نصب وابستگی ← بیلد Next ← Node قابل‌حمل ← الکترون‌بیلدر)
2. نام‌های ثابت `Peak-Setup-Latest.exe` و `Peak-Portable-Latest.exe` را می‌سازد
3. با `scripts/package-check.mjs` محتوای بسته را بازرسی می‌کند و برای هر موردِ نبوده
   **هشدار** می‌دهد (روی صفحهٔ run و در خلاصهٔ اجرا)
4. فایل‌ها را در تب **Actions** (Artifacts) می‌گذارد و در **ریلیز چرخشی** با برچسب
   `latest` منتشر می‌کند (`make_latest` روشن) — پس
   `…/releases/latest/download/Peak-Setup-Latest.exe` همیشه آخرین نسخه است.

### ساخت دستی روی سیستم خودت

```powershell
npm install
powershell -ExecutionPolicy Bypass -File scripts\build-exe.ps1
```

خروجی در پوشهٔ `dist/`:

* `Peak-Setup-<نسخه>.exe` — نصب‌کننده (NSIS)
* `Peak-Portable-<نسخه>.exe` — نسخهٔ قابل حمل
* `Peak-Setup-Latest.exe` / `Peak-Portable-Latest.exe` — همان فایل‌های بالا با نام ثابت
  (در گیت‌هاب خودکار ساخته می‌شوند؛ برای ساخت دستی هم نام‌گذاری‌شان ساده است)

بازرسی بسته:

```powershell
npm run check:package          # فقط هشدار می‌دهد
node scripts\package-check.mjs --strict   # اگر چیزی کم بود، با خطا تمام می‌شود
```

### چه چیزهایی در بسته بررسی می‌شود؟

| مورد | اگر نباشد چه می‌شود |
|---|---|
| `resources/node/node.exe` | برنامه روی سیستمی که Node ندارد باز نمی‌شود |
| `resources/app/.next/BUILD_ID` | سرور برنامه بالا نمی‌آید |
| `resources/app/node_modules/next/dist/bin/next` | پیام «فایل‌های برنامه ناقص‌اند» |
| `node_modules/better-sqlite3/build/Release/better_sqlite3.node` | حافظهٔ دائمی/دیتابیس کار نمی‌کند |

### نکته‌ها

* Node داخل خود بسته قرار می‌گیرد (`extraResources` از `vendor/node`) — روی سیستم کاربر نصب نیست.
* اگر `dist` از اجرای قبلی مانده باشد، `build-exe.ps1` اول پاکش می‌کند تا EXE کهنه منتشر نشود.
* آنتی‌ویروس گاهی فایل‌های ساخته‌شده با electron-builder را مشکوک می‌داند؛ در Windows Security استثنا بگذار.
* برای تغییر آیکون: `build/icon.ico` (حداقل ۲۵۶×۲۵۶) — اگر خراب باشد، از `build/icon.png` ساخته می‌شود.
* اگر ساخت با خطای `typescript` مواجه شد: مطمئن شو `next.config.mjs` هست (نه `.ts`).

## ۱) Ollama (محلی و رایگان)

### چه چیزی تست شده؟
- ✅ قالب درخواست/پاسخ **طبق مستندات رسمی Ollama** پیاده‌سازی شده است.
- ✅ آداپتور با یک **سرور ساختگی محلی** که دقیقاً همان مسیرهای مستندشده را پیاده کرده، تست شده
  (`tests/providers.integration.test.ts`).
- ❌ اتصال به یک نصب واقعی Ollama از محیط ساخت این سند **امکان‌پذیر نبود**
  (محیط بدون دسترسی به شبکهٔ عمومی). برای اطمینان، دستورهای زیر را روی سیستم خودتان اجرا کنید.

### نصب و راه‌اندازی (ویندوز / مک / لینوکس)

```bash
# ۱) نصب: https://ollama.com/download
# ۲) اجرای سرویس (اگر به‌صورت خودکار اجرا نشد)
ollama serve

# ۳) نصب یک مدل سبک (پیشنهاد ما برای سیستم‌های کم‌رم)
ollama pull llama3.2:3b

# ۴) دیدن مدل‌های نصب‌شده  ← این فهرست را Peak هم می‌خواند
ollama list
```

### تنظیم در Peak
| فیلد | مقدار |
|---|---|
| ارائه‌دهنده | `Ollama (محلی و رایگان)` |
| Base URL | `http://127.0.0.1:11434` (پیش‌فرض) |
| مدل | دقیقاً یکی از نام‌های `ollama list` (مثلاً `llama3.2:3b`) |
| کلید API | خالی — Ollama کلید نمی‌خواهد |

اگر Ollama روی سیستم/شبکهٔ دیگری است (مثلاً Docker یا PC دیگر):
`http://192.168.1.10:11434` و در صورت نیاز متغیر محیطی `OLLAMA_HOST=192.168.1.10:11434`.

### چه مسیرهایی صدا زده می‌شود؟
| مسیر | کاربرد |
|---|---|
| `GET {base}/api/version` | تأیید در دسترس بودن سرویس |
| `GET {base}/api/tags` | فهرست **واقعی** مدل‌های نصب‌شده |
| `POST {base}/api/chat` | تولید متن (استریم = NDJSON) |
| `GET {base}/v1/models` | فقط اگر مسیر بومی پاسخ ندهد (سازگاری با نسخه‌های قدیمی) |

اگر آدرس را با `/v1` وارد کنید، Peak خودش آن را به ریشه تبدیل می‌کند.

### تست دستی بدون Peak
```bash
curl http://127.0.0.1:11434/api/tags
curl -X POST http://127.0.0.1:11434/api/chat -H "Content-Type: application/json" \
  -d '{"model":"llama3.2:3b","messages":[{"role":"user","content":"سلام"}],"stream":false}'
```

  این تست فقط با کلید واقعی شما و اینترنت خودتان ممکن است:
  `OPENROUTER_API_KEY=sk-or-... PEAK_RUN_LIVE_TESTS=1 npm run test:live`

### راه‌اندازی
1. کلید بسازید: <https://openrouter.ai/keys>
2. کلید را **یا** در صفحهٔ «تنظیمات» وارد کنید **یا** در متغیر محیطی بگذارید:
   ```bash
   # ویندوز (PowerShell)
   $env:OPENROUTER_API_KEY="sk-or-v1-..."
   # مک/لینوکس
   export OPENROUTER_API_KEY="sk-or-v1-..."
   ```
3. تنظیمات:

| فیلد | مقدار |
|---|---|
| ارائه‌دهنده | `OpenRouter` |
| Base URL | `https://openrouter.ai/api/v1` (پیش‌فرض) |
| مدل | شناسهٔ کامل مدل، مثلاً `openai/gpt-4o-mini` |
| کلید API | کلید شما (فقط روی کامپیوتر خودتان ذخیره می‌شود) |

### مدل‌های رایگان
- مدل رایگان در OpenRouter شناسه‌اش با **`:free`** تمام می‌شود (مثلاً `deepseek/deepseek-chat-v3-0324:free`).
- Peak مدل‌های رایگان را در فهرست با برچسب «رایگان» نشان می‌دهد و تعدادشان را می‌نویسد.
- برای اینکه فقط مدل‌های رایگان نمایش داده شود: `OPENROUTER_FREE_ONLY=1`
- ⚠️ محدودیت نرخ روزانهٔ مدل‌های رایگان وجود دارد؛ اگر به 429 خوردید، پیام خطا گویا نمایش داده می‌شود.

### چه مسیرهایی صدا زده می‌شود؟
| مسیر | کاربرد |
|---|---|
| `GET /api/v1/models` | فهرست مدل‌ها |
| `GET /api/v1/key` | اعتبار کلید، کریدت باقی‌مانده، سهمیهٔ روزانهٔ مدل‌های رایگان |
| `POST /api/v1/chat/completions` | تولید متن (استریم SSE) |

هدرهای ارسالی: `Authorization: Bearer <key>`، `X-OpenRouter-Title` (نام برنامه) و
`HTTP-Referer` (در صورت تنظیم `OPENROUTER_SITE_URL`) — مطابق مستند رسمی.

### خطاهایی که Peak دقیق تشخیص می‌دهد
| کد | معنی |
|---|---|
| 401 | کلید نامعتبر یا ارسال نشده |
| 402 | کریdit کافی نیست |
| 403 | محدودیت بودجه |
| 429 | محدودیت نرخ درخواست |

## ۳) 9Router (اختیاری)

### 9Router چیست؟
طبق مخزن رسمی [`decolua/9router`](https://github.com/decolua/9router) و بستهٔ npm
[`9router`](https://www.npmjs.com/package/9router): یک **پروکسی محلی OpenAI-Compatible**
است که درخواست‌ها را بین چند ارائه‌دهندهٔ دیگر مسیریابی می‌کند.

### چه چیزی تست شده؟
- ✅ وجود و مستندات رسمی بررسی شد (README مخزن + رجیستری npm، نسخهٔ 0.5.104، MIT).
- ✅ فقط از مسیرهای **مستندشده** استفاده می‌کنیم: `GET {base}/models` و `POST {base}/chat/completions`.
- ❌ چون Peak در این پروژه با 9Router اجرا نشده، این ارائه‌دهنده **اختیاری** است.
  اگر 9Router روی سیستم شما نبود یا روی پورت دیگری بالا آمده بود، هیچ چیز خراب نمی‌شود.
- ⚠️ هیچ endpoint یا مدلی اختراع نشده است. اگر رفتار متفاوت بود، Peak خطای گویا می‌دهد.

### راه‌اندازی
```bash
npm install -g 9router
9router
# داشبورد: http://localhost:20128
# API سازگار با OpenAI: http://localhost:20128/v1
```
(طبق README رسمی؛ اگر پورت را با `PORT` تغییر داده‌اید، همان را در Base URL وارد کنید.)

### تنظیم در Peak
| فیلد | مقدار |
|---|---|
| ارائه‌دهنده | `9Router (پروکسی محلی — اختیاری)` |
| Base URL | `http://127.0.0.1:20128/v1` |

## ۴) تشخیص (Diagnostics)

### از خط فرمان
```bash
npm run diagnose                                   # تنظیمات ذخیره‌شده
npm run diagnose -- --provider ollama             # تست بدون ذخیره
npm run diagnose -- --provider openrouter --model openai/gpt-4o-mini

```
کد خروج: `0` = بدون FAIL، `1` = حداقل یک FAIL، `2` = خطای اجرا.

### از HTTP
```bash
curl http://127.0.0.1:3784/api/health          # سلامت بک‌اند و دیتابیس
curl http://127.0.0.1:3784/api/diagnostics     # گزارش کامل
curl -X POST http://127.0.0.1:3784/api/diagnostics \
  -H 'Content-Type: application/json' \
  -d '{"provider":"ollama","baseUrl":"http://127.0.0.1:11434","model":"llama3.2:3b"}'
```

خروجی هر مرحله یکی از این چهار وضعیت است:

| وضعیت | معنی |
|---|---|
| `PASS` | واقعاً تست شد و موفق بود |
| `FAIL` | تست شد و شکست خورد (همراه با راه‌حل) |
| `NOT_TESTED` | قابل تست نبود (مثلاً ربات ماینکرفت وصل نیست) |
| `SKIPPED` | به‌دلیل پیکربندی ناقص، تست انجام نشد |

مراحلی که بررسی می‌شوند: پیکربندی → دسترسی‌پذیری → احراز هویت → مدل‌های نصب‌شده →
مدل انتخابی → **یک تولید متن واقعی** → دیتابیس → ربات ماینکرفت.

## روش‌ها

1. **از داخل برنامه**: صفحهٔ «مودها» ← «ساخت مود جدید»
2. **فایل JSON**: فایل `.json` را داخل پوشهٔ `data/mods/` بگذار (مثلاً `my_pack.json`)

## ☕ مودهای جاوا (.jar) — Minecraft Java Edition

علاوه بر مودهای JSON، می‌توانی مودهای واقعی جاوا (مثل مودهای **Forge/Fabric** با پسوند `.jar`) را هم مدیریت کنی:

1. **افزودن**: صفحهٔ «مودها» ← بخش «مودهای جاوا» ← فایل `.jar` را آپلود کن (در `data/mods/java/` ذخیره می‌شود)
2. **روشن/خاموش**: با دکمهٔ هر مود — مود خاموش از بازی نصب نمی‌شود
3. **مسیر بازی**: مسیر پوشهٔ `mods` بازی‌ات را بنویس (مثلاً `.../.minecraft/mods` یا پوشهٔ mods سرور) و «ذخیرهٔ مسیر» را بزن
4. **نصب**: «نصب مودهای روشن در بازی» — همهٔ فایل‌های `.jar` روشن در پوشهٔ mods بازی کپی می‌شوند

نکته‌ها:
- فقط فایل `.jar` سالم پذیرفته می‌شود (حداکثر ۲۰۰ مگابایت) — فایل‌های جعلی رد می‌شوند
- برای اینکه مودها داخل بازی لود شوند، بازی/سرور باید **Forge** یا **Fabric** نصب داشته باشد
- این بخش هیچ فشاری روی سیستم ندارد؛ فایل‌ها فقط هنگام درخواست تو جابه‌جا می‌شوند

## ساختار یک مود

```json

  "name": "مود من",
  "version": "1.0.0",
  "author": "نام تو",
  "description": "توضیح کوتاه",
  "enabled": true,
  "commands": [
    {
      "id": "c1",
      "label": "عنوان دستور",
      "samples": ["جمله اول", "جمله دوم"],

    {
```

## انواع دستور

| نوع | فیلد | کار |
|---|---|---|
| پاسخ متنی | `reply` | فوری و بدون اینترنت جواب می‌دهد |
| دستور سرور | `op` | دستور اسلش ماینکرفت (نیاز به OP) |
| توانایی | `capability` | یکی از ۴۴۵ توانایی داخلی (مثل `god_kit`، `god_seal_on`، `castle_op`، `follow`) |

## نکته‌ها

* در `op` می‌توانی از `{player}` (نام بازیکن)، `{self}` (نام ربات) و `{n}` استفاده کنی.
* `samples` جمله‌های فعال‌ساز هستند — با صوت یا متن گفته شوند، اجرا می‌شود.
* مودها فقط JSON ساخت‌یافته‌اند؛ **کد اجرا نمی‌شود** → امن و سبک.
* هر مود حداکثر ۱۰۰ دستور.
* از صفحهٔ مودها می‌توانی هر مود را روشن/خاموش یا حذف کنی.
